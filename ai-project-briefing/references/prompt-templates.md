# 需求分析与中文 SRS 实战提示词模板

本文件供用户或 AI 在 Stage 1（`ai-project-briefing`）各环节中使用，覆盖需求深挖、模块拆解、11 项功能用例表编写、MVP 收敛与验收口径自检。

---

## 1. 产品立项与业务盲区追问

```text
当前处于需求分析与立项阶段，请暂时不要写任何代码，也不要急于确定具体编程框架。
请以高级产品架构师的角色，针对我的项目想法做一轮业务深挖：
项目想法：[用一两句话描述你的项目]

请帮我整理并逐一确认以下 6 个核心问题（每次聚焦 1–2 个最关键的缺失点追问我）：
1. 目标用户与使用场景：谁在什么场景下使用？解决什么现有方案搞不定的痛点？
2. 端到端核心主流程：从发起到最终完成，最关键的 3–6 个步骤是什么？
3. 角色与数据归属：系统有哪些角色？谁能看全局，谁只能看自己名下的数据？
4. 业务状态与红线约束：核心单据/记录有哪些状态？什么状态下禁止修改、删除或越权操作？
5. 第一版 MVP 边界：哪些是 P0 必做？哪些留到 P1/P2？哪些明确不做？
6. 量级与非功能要求：首年用户量和数据量级大概多少？需要对接哪些外部系统或终端？
```

## 2. 模块拆解与功能用例目录收敛

```text
请基于我们已经确认的产品目标与主流程，为我规划中文《需求规格说明书》的模块结构与第 3 章功能用例目录。

要求：
1. 按“3.X 业务模块 → 3.X.Y 子模块 → 3.X.Y.Z 具体用例”的三级结构列出完整用例清单。
2. 为每个用例标注优先级（P0 必做 / P1 后续）与核心参与者。
3. 如果存在结构高度重复的辅助操作（如各基础主档的启用/禁用），请标明“可复用主用例 + 差异点”。
4. 先输出模块与用例目录清单让我确认，暂不展开具体表格。
```

## 3. 标准 11 项功能用例规格表生成

```text
请为以下功能模块编写完整的第 3 章中文功能用例规格，严格遵循 `references/srs-template.md` 中的 11 项表格结构：
模块名称：[如：3.3 入库管理]
包含用例：[列出该模块下要编写的用例清单]

每个核心用例必须完整包含以下 11 行：
1. 名称
2. 优先级（高/中/低）
3. 功能描述（触发来源与业务价值）
4. 参与者
5. 前置条件（约束）（必须写清权限要求、允许操作的状态集合、唯一性与归属约束）
6. 事件流（操作序列）（按步骤编号）
7. 可选事件流（校验失败、状态不满足、取消返回、并发冲突等异常分支）
8. 后置条件（默认初始状态、单号自动生成规则、主从表联动更新）
9. 数据描述（逻辑业务字段、建议英文名、业务类型、必填性、状态枚举与唯一约束；暂不写死物理索引）
10. 补充说明（业务常识解释、具体数字/单号示例、特殊规则）
11. 修改历史

请确保语言为规范中文，不要用“按常规处理”“自行校验”等模糊表述敷衍关键规则。
```

## 4. MVP 边界与 Non-Goals 审校

```text
请以“严控 v1 交付周期”的视角审校当前需求清单：
1. 哪些功能其实是“锦上添花”，去掉后不影响核心主流程闭环？（建议降级为 P1 或 Non-Goals）
2. 哪些看似简单但实现复杂度极高的隐形坑需要警惕？（如：自定义审批流引擎、多租户隔离、复杂报表、分布式事务）
3. 针对每个被砍掉或延后的功能，给出 v1 阶段最简单的人工或轻量替代方案。
```

## 5. 中文 SRS 质量自检与下游就绪核对

```text
请对照以下清单自检 `specs/project-brief-spec.md`（及 `specs/modules/*.md`）是否已达到交付给 Stage 2–5 的标准：
1. 是否全篇采用规范中文撰写（引言、系统介绍、功能用例、非功能需求与验收标准四章齐全）？
2. 第 2 章是否包含业务架构图、端到端流程图、角色权限矩阵、MVP 分层清单、核心对象与状态机图？
3. 第 3 章每个核心用例是否都有明确的前置状态约束、异常分支（可选事件流）与后置状态/编号规则？
4. 数据描述是否包含关键业务字段和归属关系（如 user_id/owner_id），且没有越界把 Stage 2 技术选型写死？
5. 第 4 章验收标准是否全部可客观测试，是否存在未记录到“待确认问题”表的悬空假设？

如有缺失或模糊项，请逐条指出并补充完整后再提示我进入 Stage 2（ai-tech-advisor）。
```
