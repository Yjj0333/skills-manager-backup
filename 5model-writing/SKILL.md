# 建模章节撰写

本 skill 只负责把已经建立、求解并验证过的数学模型写成竞赛论文中的建模部分。默认产出引擎无关的 `reports/MODEL_SECTION_DRAFT.md`，供 `5writing` 装配到比赛模板；用户明确指定排版引擎且已有模板时，才可同步生成对应的章节文件。

## 边界

- 上游：读取 `reports/ANALYSIS_MODELING_REPORT.md`、`reports/RESULTS_REPORT.md`，可选读取 `reports/DRAWIO_REPORT.md` 和 `figures/*`。
- 本阶段：写问题分析、模型假设、符号说明、各子问题的模型建立/求解/结果解释、敏感性与模型局限。
- 不负责：选模型、改公式、运行代码、生成数值结果、绘制数据图、制作 DrawIO 图、编写完整摘要/参考文献/代码附录或最终验收。
- 上游报告缺字段时，记录缺口和待补证据，不以常识补写事实；发现模型本身错误时退回 `2analysis-modeling`。

## 输入门

开始前检查：

1. `ANALYSIS_MODELING_REPORT.md` 是否声明动态子问题数量、任务角色、DAG 接口、变量/参数、假设、目标、约束、求解器和验证计划。
2. `RESULTS_REPORT.md` 是否给出实际运行配置、结果表、误差/可行性/最优性证据和可引用的图表文件。
3. 每个结果是否能映射回一个子问题、一个模型输出和一个来源。
4. `DRAWIO_REPORT.md` 或 `figures/*` 中的图是否有名称、用途和对应章节。

若第 1 或第 2 项不满足，先输出“写作阻断清单”，不生成看似完整的正文。

## 六段闭环

不同任务角色的验收证据和结果段写法见 [references/model-role-writing.md](references/model-role-writing.md)，只在当前子问题需要时读取。

每个子问题只按下列顺序写，标题可按竞赛模板改写但语义不能缺失：

1. **任务与接口**：说明题面要求、输入、输出、与上游变量的继承关系，以及新增状态/约束的来源。
2. **变量与假设**：只列正文实际使用的符号；给单位、类型、范围和来源。假设同时写依据、影响和验证/替代办法。
3. **基线与缺陷诊断**：交代最小充分基线和为何需要（或不需要）升级；不能以“更先进”作为理由。
4. **数学表达与求解规格**：从输入关系到状态、目标、约束、输出形成闭合公式链；分开写模型、求解器和精确性等级 `E0/E1/N/H`。
5. **验证与结果解释**：按角色引用真实证据。预测写样本外误差和区间覆盖；优化写可行性、目标界/间隙和运行时间；机理写量纲、守恒、边界和步长收敛；评价/分类/网络/博弈使用对应证据。
6. **结果与下游交接**：先给来源可追溯的结论，再解释业务/物理意义；明确哪些变量、参数、不确定性和图表交给下一问或整篇论文。

## 论文结构

默认草稿按以下顺序组织，子问题数量以报告声明为准，不硬编码三问或四问：

```text
# 建模章节草稿
## 输入与范围
## 题面任务—模型映射
## 问题分析与总体路线
## 模型假设
## 符号说明
## 问题一：模型建立与求解
  ### 任务与接口
  ### 变量与假设
  ### 基线与缺陷诊断
  ### 数学表达与求解规格
  ### 验证与结果解释
  ### 结果证据
  ### 下游交接
## 问题二：模型建立与求解
...
## 敏感性、稳定性与局限
## 建模章节交接
```

“结果证据”必须使用如下最小表，并在正文段落中引用它；数值、方向和单位只能来自结果报告或已生成图表：

```markdown
| 结论 | 数值/方向 | 来源 | 图表/表格 |
| --- | --- | --- | --- |
| ... | ... | reports/RESULTS_REPORT.md | 图/表编号 |
```

## 数学表达规则

- 变量、参数、单位在全文保持一致；同一符号不能在不同问题中无声明换义。
- 公式至少覆盖定义/状态关系、目标函数、约束和输出映射；不以公式数量作为质量指标。
- 优先使用可解释的解析、枚举、动态规划、网络流、MIP、凸优化或确定性 NLP；启发式只在报告说明精确方法不可行时出现，并写清随机重复、小规模精确基准和回退方案。
- `E0` 只表示明确假设、给定离散化或有限策略空间内的解析/完全枚举精确；`E1` 表示全局最优证明或可接受最优间隙；`N` 报告容差和收敛；`H` 只称当前最好可行解，不称全局最优。
- 不把求解精确性写成现实机制绝对准确；现实有效性放在验证证据中讨论。
- 图表必须有编号、单位、图注/表注和正文引用。三线表是排版建议，不把 Markdown 网格直接当最终版式。

## 结果与证据纪律

- 不估算、补齐或改写 `RESULTS_REPORT.md` 中没有的数值；没有运行结果就写“待运行/待核验”，并列入交接清单。
- 不把算法名、相关性、回归系数、灰色关联、SHAP 或漂亮图形写成因果证据；因果表述必须有识别设计和假设支撑。
- 灵敏度范围来自物理边界、置信区间、业务范围或数据分位数，不固定套用 ±5% 或 ±10%。
- 结果段先报告事实，再解释原因，最后说明适用边界；禁止“极强鲁棒性”“大幅提升”等没有比较对象和证据的绝对化句子。

## 写作与交接

正文用连贯的学术段落连接公式、表格和图，不照抄题面，不堆算法名，不插入完整代码。每个子问题结束时写一个短结论，包含：模型输出、证据来源、验证状态、限制和下游接口。

默认完成后运行：

```powershell
python "$env:USERPROFILE\.skills-manager\skills\5model-writing\scripts\validate_model_section.py" reports/MODEL_SECTION_DRAFT.md
```

校验器只做结构和证据门，不替代人工检查公式含义、单位、论证逻辑和竞赛模板格式。将通过校验的草稿交给 `5writing`，由其选择 Typst/LaTeX、模板、章节文件名并装配整篇论文。

## 完成前清单

- [ ] 每个动态子问题都有一节，且没有伪造依赖。
- [ ] 任务、变量/假设、基线诊断、数学表达、求解规格、角色化验证、证据和下游接口均出现。
- [ ] 所有数值和图表有 `RESULTS_REPORT.md` 或 `figures/*` 来源。
- [ ] 目标函数、约束、输出和求解器相互一致，精确性等级没有夸大。
- [ ] 占位符、未定义符号、重复结论和内部路径泄露已清理。
- [ ] 已运行 `validate_model_section.py`，并把剩余人工审阅项交给 `5writing`/`6verity`。
