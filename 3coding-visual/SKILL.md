# 编程实现、求解验证与数据图表生成

承接 `2analysis-modeling`，把建模报告中的公式、算法、约束和验证方案落实为可复现程序。先得到可信且可追溯的真实结果，再通过 `$model-figure-selector` 决定画什么，最后生成可直接交给 `5writing` 的数据型图表和结果记录。

## 阶段边界

- 负责：数据读取与必要预处理、模型/算法实现、实验运行、约束与误差验证、结果序列化、灵敏度/稳健性实验、数据型图表、`reports/RESULTS_REPORT.md`。
- 不负责：技术路线图、通用算法流程图、系统架构图、概念示意图和纯结构型模型图；将这些交给 `4drawio`。
- 不负责：撰写完整论文正文；只提供经验证的数值、表格、图表、caption/label 建议和正文分析要点。
- 不得静默修改 `reports/ANALYSIS_MODELING_REPORT.md` 中的模型、约束、参数或结论。确需替代时，先说明原因、替代方案和影响，再在结果报告中保留差异记录。

数据驱动的网络、最优路径、布局、可行域和仿真状态图属于本阶段；不依赖求解数据的流程、层次和概念结构图属于 `4drawio`。

## 必读规范与按需引用

- 涉及题型、实现或图表判断时，读取 `../_references/math_modeling_norms.md` 中的“题型防错速查”“代码实现与结果”“编码阶段常见错误”“图表与可视化”和“非数据图工具选择”。
- 进入求解后制图阶段前，完整读取 [references/model-figure-selector-handoff.md](references/model-figure-selector-handoff.md)，按其中的输入、输出、缺数修复和跨 Skill 边界执行。

## 先识别项目合同

开始前读取实际存在的 `plan.md`、`todo.md`、题面与附件、`reports/ANALYSIS_MODELING_REPORT.md`、现有 `code/`、`results/`、`figures/` 和 `reports/RESULTS_REPORT.md`。

- 服从 `plan.md` 已确定的目录结构；不要为同一类结果另建平行目录。
- 默认将源代码放入 `code/`，机器可读结果、日志和图表数据放入 `results/`，最终图片放入 `figures/`，阶段报告放入 `reports/`。
- 若项目已有不同但一致的布局，沿用现状并在结果报告中说明，不做无意义迁移。
- 重跑已有项目时，不要在新结果通过验证前覆盖权威旧结果。优先写入独立运行目录或临时输出，再明确提升为当前结果。

## 执行工作流

### Step 0：输入与环境门禁

1. 确认建模报告、原始数据和必要附件可读；缺少关键输入时，列出阻塞项，不伪造数据继续求解。
2. 检查编码、列名、形状、类型、单位、缺失值、重复值、异常值、时间顺序和主键对齐。
3. 记录语言与包版本、硬件/求解器版本、入口命令、随机种子和外部依赖。
4. 把每个子问题的输入、预期输出、模型、约束、验证指标和权威结果文件建立映射。

### Step 1：拆分可复现实现

按子问题顺序实现，不要一次写完后统一试跑。为每个子问题明确：

- 数据加载与预处理；
- 模型、目标函数和约束；
- 求解器或算法；
- 结果序列化；
- 约束、误差或守恒验证；
- 灵敏度、稳健性或重复运行设计；
- 后续图表需要记录的真实诊断数据。

让公共读取、验证和绘图逻辑可复用，但避免为了“框架整齐”改变数学含义。

### Step 2：逐子问题闭环

每个子问题依次完成：

1. 读取并审计真实输入；
2. 实现与建模报告一致的模型；
3. 先跑最小可验证样例或小规模实例；
4. 运行正式求解；
5. 回代检查全部约束、边界、单位和物理意义；
6. 保存核心结果和必要中间过程；
7. 更新 `reports/RESULTS_REPORT.md`；
8. 通过当前子问题验收后再进入下一问。

不要以“程序无异常退出”代替数学验证，也不要只相信求解器的 `success` 标志。

### Step 3：按模型类型验证

- 优化类：先确认严格可行，再比较目标；记录每条约束值、边界、松弛量和违反量。启发式结果称为“当前最好/最佳已知解”，除非有全局最优证明。
- 随机/智能优化：固定并记录种子；需要稳定性结论时运行多个独立种子，保存每次目标值、可行性、耗时和关键解。只有一次运行时明确写“未验证随机稳定性”。
- 预测/机器学习：按任务正确划分训练、验证和测试；时序不得随机打乱；所有 scaler/encoder 只在训练集拟合；保存逐样本预测、误差和概率/得分。
- 评价/决策：记录指标方向、无量纲化公式、权重来源、权重和、最终得分、排名及敏感性实验。
- 微分方程/仿真：记录初边值、单位、求解器、步长、守恒/漂移和步长收敛检查。
- 图论/路径：验证有向性、连通性、权重、容量、流守恒、子回路、时间窗和路径可行性。

首次可行、首次越过阈值、收敛或触发终止等事件必须在运行时精确记录。不要从稀疏历史点事后推断事件时刻。

### Step 4：冻结可追溯结果

在任何论文图表生成前，先形成可复现的结果快照。至少保存：

- 输入版本、数据行列数和预处理摘要；
- 模型参数、求解器配置、随机种子和运行命令；
- 各子问题核心数值与单位；
- 逐项约束/一致性/守恒/误差检查；
- 迭代历史、逐样本预测、方案坐标、权重排名或仿真轨迹等后续绘图源；
- 多次运行、灵敏度和稳健性实验的每次真实结果；
- 运行时间、终止原因、警告、失败和不可行记录。

优先使用 JSON、CSV、NPZ 或其他机器可读格式。Markdown 报告不是唯一数值源；图表也不能成为唯一结果存档。

### Step 5：强制执行图表智能匹配

求解完成、验证通过并冻结结果后，**在编写或运行论文绘图代码前必须调用 `$model-figure-selector`**。

按 [references/model-figure-selector-handoff.md](references/model-figure-selector-handoff.md) 向其提供：

- `reports/ANALYSIS_MODELING_REPORT.md`；
- 当前 `reports/RESULTS_REPORT.md`；
- 机器可读结果与运行日志清单；
- 每个子问题的模型、核心结论、验证结论和可用诊断数据；
- 论文语言、图表目录和本阶段只生成数据图的边界。

要求它先完成“模型识别 → 论文论证任务 → 数据充分性 → 候选图表评分 → 核心图表链 → 绘图库 → 插入位置/caption/label”的完整规划。

- 不再执行“绘制丰富图表”这种数量导向要求。
- 通常每个子问题只保留 2～4 张能够增加证据的图。
- 如果删图不会削弱任何结论、验证或稳健性证据，则不画。
- 若 `$model-figure-selector` 在当前项目不可用，停止图表子阶段，报告依赖缺失；可继续交付已验证代码和结果，但不得声称本 Skill 已全部完成。
- 若它指出数据不足，只能通过真实重跑补录合法诊断；不得编造收敛历史、多次运行、概率、置信区间或敏感性结果。

### Step 6：只实现入选图表

1. 按选择结果使用 Matplotlib、Seaborn、Plotly、NetworkX、igraph、GeoPandas、Folium、Graphviz 或 Plotnine 等合适工具，不把 `$nature-figure` 当绘图库。
2. 当 `$model-figure-selector` 把静态论文图路由给 `$nature-figure` 时，遵守其当前后端、学术审美、导出和渲染 QA 规则。
3. 使用冻结的真实结果文件作图，不在绘图脚本中硬编码论文数值。
4. 为同一算法、对象、状态或方案保持全篇一致的颜色、线型、标记和图例顺序。
5. 输出 PDF 或 SVG，并输出 300 DPI 以上 PNG；文件名稳定、语义清楚。
6. 图内不放大标题；坐标轴、单位、图例和注释使用论文语言，标题交给 Typst/LaTeX caption。
7. 将图表专用派生数据保存在 `results/`，不要把 CSV、日志和中间缓存混入最终 `figures/`。

### Step 7：回填结果报告

`reports/RESULTS_REPORT.md` 按实际子问题数量组织，不硬编码三问。建议结构：

```markdown
# 计算结果

## 运行环境与复现入口
## 数据读取与预处理审计
## 各子问题实现、结果与验证
## 灵敏度与稳健性
## 图表证据与文件映射
## 约束、一致性与结果源检查
## 与建模报告的差异说明
## 可复现运行方式
```

报告必须：

- 引用所有会进入论文的关键数值、结果表和最终图表；
- 对每张图记录所支持的结论、数据源、文件、caption/label 和建议插入位置；
- 区分完成的实验、未运行的验证和因数据不足未生成的图；
- 保持数值精度与机器可读结果一致，不在报告阶段重新估算。

### Step 8：阶段验收

只有同时满足以下条件才声明阶段完成：

- 入口命令能够从真实数据重新生成核心结果；
- 各子问题模型、参数和约束与建模报告一致，或差异已显式记录；
- 关键结果存在机器可读来源，约束/误差/守恒检查通过或失败已如实披露；
- 随机性、灵敏度和稳健性结论具有相应真实实验；
- `$model-figure-selector` 已完成图表决策，入选图均能说明其论文证据任务；
- 每张最终图都能追溯到真实数据和绘图代码，并有 PDF/SVG、PNG、caption/label 与插入建议；
- 图表完成最终尺寸检查，无中文乱码、遮挡、缺失单位或误导性编码；
- `reports/RESULTS_REPORT.md` 与机器结果、图表标注一致；
- 没有把非数据流程图冒充为本阶段结果，也没有编造实验或结论。

若环境、数据或依赖阻止某项验收，准确列出已通过层级和剩余阻塞，不把局部运行成功表述为完整交付。
