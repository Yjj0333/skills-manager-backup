# Prompt Templates for Backend Skeleton Building

## 1. Confirm Language and Framework

```
请根据项目架构设计文档确认当前后端语言和框架是否适合本项目。不要重新发散选型，只判断是否存在为了"高级感""性能感"或"安全感"而过度选型的问题。如果当前语言或框架较重，请说明项目为什么真的需要它，以及后续必须遵守哪些成熟框架规范和最佳实践。
```

## 2. Generate Architecture Design Document

```
请根据立项文档和已确定的后端语言框架，整理项目架构设计文档。不要写业务代码。文档必须写清楚：
- 后端语言和框架选择原因，不选其他方案的原因
- 必须遵守的语言工程规范
- 必须遵守的框架最佳实践
- 框架最大化利用原则
- 目录约束
- 接口响应规则
- 错误处理规则
- 日志规则
- 数据库连接方式
- 权限校验入口
- 以后新增模块应该怎么放文件
```

## 3. Build Minimal Skeleton

```
请严格根据项目架构设计文档，基于当前后端语言和框架，按照该语言工程规范、该框架官方文档或主流最佳实践，搭建最小可运行后端骨架。先说明目录结构、目录作用、哪些是框架推荐、哪些是项目自定义。不要先写完整业务功能。骨架必须包含：项目启动入口、环境变量配置、路由分组、健康检查接口、数据库连接、统一响应格式、统一错误处理、日志基础、参数校验、权限中间件占位、README 启动说明。
```

## 4. Agent Constitution Rule

```
后端开发必须遵守当前语言工程规范和框架最佳实践，优先复用框架能力。新增依赖、目录调整、错误码自定义、框架更换，都要先说明原因，并更新项目架构设计文档。
```

## 5. Verify Skeleton Startup

```
请验证后端骨架是否可以正常启动。执行依赖安装、启动服务、访问健康检查接口、确认配置读取、确认日志输出。每一步给出实际执行结果。
```
