# CUMCM B 四问论文交接合同

仅在确认使用项目内 `5writing` 的 CUMCM B 题 LaTeX 工作流时读取。本文定义 `reports/ANALYSIS_MODELING_REPORT.md` 应向代码阶段和论文阶段提供的字段，不是可以直接提交的论文正文。

## 1. 合同头

报告开头使用表格记录：

| 字段 | 要求 |
|---|---|
| competition | `CUMCM` |
| problem | `B` |
| typesetting_engine | `LaTeX`；若用户另有选择则据实填写 |
| question_count | 默认 `4`；题面明确时以题面为准 |
| validation_layout | `per-question`、`unified` 或 `main-model-only`，三选一 |
| main_model_problem | 主要模型所在问题编号；不适用时写“无单一主要模型” |
| evidence_state | 仅记录“待求解”“数据不足”或已有真实证据，不写预期数值 |

同时列出题面来源、附件清单、单位口径、关键歧义和未决风险。

## 2. 推荐报告结构

```markdown
# 建模报告

## 0. 赛题与论文交接合同
## 1. 题意核对与总体建模框架
## 2. 四个问题的逐问分析
### 2.1 问题一分析
### 2.2 问题二分析
### 2.3 问题三分析
### 2.4 问题四分析
## 3. 数据与附件理解
## 4. 模型假设
## 5. 主要符号说明
## 6. 问题一模型设计
## 7. 问题二模型设计
## 8. 问题三模型设计
## 9. 问题四模型设计
## 10. 模型检验布局与证据计划
## 11. 代码实现任务清单
## 12. 论文与支撑材料交接
```

若题面明确不是四问，按真实问数增删对应章节，后续编号顺延。

## 3. 逐问问题分析字段

每问的分析必须用连贯内容回答：

1. 本问要求完成什么、为什么重要、核心输出是什么；
2. 属于哪类数学任务，哪些一般方法适用；
3. 对应附件的规模、变量类型、时空属性、缺失、异常、量纲和相关性；
4. 是否需要数据处理，若需要则写明方法、原因和影响；
5. 结果形式、精度、单位、约束和评价标准；
6. 主模型与必要对比模型的选择依据；
7. 本问输出如何进入下一问。

不要固定写成评价、预测、PCA 或特征工程套路。

## 4. 模型假设和符号字段

每条假设记录：

- 假设内容；
- 题面、物理或业务依据；
- 简化的对象；
- 对哪个公式或约束生效；
- 失效边界及可能影响。

符号表只收录全文反复使用的主要符号，并记录唯一含义、单位、取值域和首次使用问题。局部临时变量留在正文首次出现处说明。

## 5. 每问模型设计字段

问题一至问题四均使用以下结构：

```markdown
### 任务、模型类型与上下问关系
### 建模思路与模型选择
### 变量、参数与数据来源
### 模型的建立
#### 核心关系或机理
#### 目标函数
#### 约束、初边值或状态转移
#### 模型汇总
### 模型的求解方案
#### Step 1：...
#### Step 2：...
### 预期输出与权威结果字段
### 模型检验与灵敏度计划
### 论文证据与绘图数据需求
```

“模型汇总”必须集中给出最终完整方程、目标、约束、变量类型与范围，不能只引用前文零散公式。

求解步骤必须说明算法输入、初始化、核心更新、停止条件、失败或不可行处理、结果序列化和约束回代。步骤数量按真实方法调整。

## 6. 检验布局合同

### `per-question`

用于模型类型差异明显的四问。每问列出 1～2 项论文级检验以及真实数据需求，目标位置为对应的 `5.x.5 模型检验与灵敏度分析`。

### `unified`

用于同一或同类模型贯穿全文。逐问仍规划内部数学检查，但论文级指标统一映射到可选的“模型的分析与检验”章；不得同时要求四个 `5.x.5` 重复展示。

### `main-model-only`

用于只有一个主要模型决定最终结论的情形。记录主要问题编号，只有该问规划完整论文级检验；其余问题仍保留必要的数学正确性和可行性门禁。

## 7. 检验和灵敏度字段

每项论文级检验记录：

| 字段 | 内容 |
|---|---|
| target_claim | 要验证的数学或结论主张 |
| method | 与模型匹配的方法，不使用代码自检 |
| metric | 指标及单位 |
| criterion | 判定依据或比较基准 |
| required_data | 代码阶段必须保存的真实字段 |
| paper_target | 对应 `5.x.5` 或统一分析章 |
| status | `planned`、`data-insufficient`，分析阶段不得写 `passed` |

灵敏度项目还要记录参数的现实含义、基准来源、合理变化范围、保持不变的条件以及可能影响的决策结构。不得为了形式完整随意选择参数。

## 8. 证据需求合同

每个核心结论记录 `claim_id`，并列出：

- 结论对应的模型和问题；
- 需要保存的权威结果字段；
- 适合承担的数据认识、模型建立、算法求解、核心结果、模型验证或稳健性任务；
- 预期论文位置；
- 缺失字段和合法补算方式。

这里不固定图形类型。最终候选图必须在真实求解、验证和结果冻结后交给 `$model-figure-selector` 判断。

## 9. 代码实现任务表

```markdown
| task_id | 问题 | 输入 | 数学模型 | 求解步骤 | 权威输出 | 内部门禁 | 论文级检验 | 后续依赖 |
|---|---|---|---|---|---|---|---|---|
```

任务表不得填写不存在的文件或预先断言检验通过。

## 10. 论文与支撑材料交接

交接部分只记录能够由后续阶段兑现的内容：

- 四问的输入输出链；
- 模型优点可能需要的量化证据；
- 已知限制、适用边界及对应改进方向；
- 预期代码入口和机器可读结果类型；
- 需要保留的完整程序、环境信息和补充推导；
- 已知 AI 工具、使用阶段、主要提示目的、人工采纳修改与核验计划。

没有真实运行前，不得写最终得分、误差、最优值、提升率、稳定区间或图表结论。
