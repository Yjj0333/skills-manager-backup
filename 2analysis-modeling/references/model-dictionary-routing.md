# 模型字典路由合同

本合同规定 `2analysis-modeling` 如何调用可用的 `$bzd-model-dictionary`，把 5713 条只读模型记录转化为候选模型核验，而不是把字典当成自动选模器。

## 触发条件

满足任一条件时执行路由：

- 用户指定了准备采用的模型，需要判断是否适合题目和数据；
- 同一任务存在两个以上候选模型，需要比较适用边界；
- 题目、数据结构或约束与常用模型不匹配，需要寻找替代或配套模型。

若仅做题意拆解、数据审计或不涉及模型选择的格式工作，可以不触发。

## 调用输入

调用前必须先完成题面和数据初审。提交给字典 Skill 的内容至少包括：

```text
候选模型：<模型名称；多个候选逐个列出>
题面任务：<当前问题的完整任务描述>
数据证据：<文件路径或字段、样本单元、规模、时间/空间结构、缺失、重复、目标变量和约束>
期望输出：<预测/排序/决策/路径/资源配置/机理解释等>
```

数据事实未知时写“未知”，不能用字典中的一般数据要求替代本题证据。

## 查询和记录规则

1. 只查询实际进入比较的候选模型及必要的替代/配套模型，不输出整部 JSON。
2. 保留查询返回的记录 ID、模型名称、模型大类、具体分组和资料使用声明；同名不同用途记录不得合并。
3. 分开记录两类信息：
   - `dictionary_facts`：字典给出的场景、数据要求、原理、输入、输出、关键假设、禁忌点、缺陷和检验方法；
   - `case_assessment`：结合当前题面和数据得到的适配性证据、缺口和判断。
4. 每个候选给出一个判断：`合适`、`有条件合适`、`不合适` 或 `证据不足，待人工复核`。
5. 需要替代模型时，替代模型也必须经过查询；说明它是替换、预处理、验证还是配套模型。

## 写入建模报告的最小字段

```yaml
model_dictionary_review:
  status: executed | unavailable | not_required
  selected_model: <模型名或待定>
  records:
    - record_id: <字典记录 ID>
      model_name: <模型名>
      category: <模型大类/具体分组>
      dictionary_facts: <与当前问题相关的事实摘要>
      case_assessment: <本题证据和适配性分析>
      verdict: <四种判断之一>
  primary_model: <最终候选或待定>
  alternatives: <替代/配套模型及作用>
  evidence_to_collect: <代码阶段必须保存的数据和检验输出>
  unresolved: <缺失信息和人工复核事项>
```

`status: unavailable` 时只能说明未执行字典核验，不能伪造 record ID 或适配性结论。

## 与后续阶段的边界

- `2analysis-modeling` 负责提出候选、解释选择和列出证据需求，不运行正式求解。
- `3coding-visual` 负责按主模型合同实现、验证并冻结真实结果；不因字典推荐而跳过基准或约束检验。
- `$model-figure-selector` 仍在结果冻结后决定论文图；字典的模型类别不能直接变成固定图表模板。
- `5writing` 只消费建模报告、冻结结果和图表 manifest，不把字典摘录当作本题实验结果。

## 最低质量门禁

- 候选模型来自题面任务、数据结构和约束，而非只来自热门程度；
- 字典事实和本题判断可追溯且没有混写；
- 数据不足、模型身份歧义或关键假设无法验证时，保留“证据不足”；
- 不输出无关记录、不覆盖只读字典、不编造样本量、分布、精度或验证结果。
